# Scardice-ui

> 余烬核心的前端实现

## 说明

本仓库为余烬核心的前端实现，使用 Vue3 + ElementPlus + tailwindcss 开发。

后端仓库：[Scardice-core](https://github.com/Scardice/Scardice-core)

此仓库的 Issue 已关闭，请在后端仓库中提交 Issue。包括与前端相关的 Issue。

## 界面导航

- 左侧导航按运行与账号、自定义文案、扩展功能、综合设置和辅助工具分组。
- 使用 `Ctrl+K`（macOS 上使用 `⌘+K`）搜索并跳转到页面。
- 在顶部切换舒适、紧凑或极紧凑密度；工作区会按页面和屏幕宽度调整布局。
- 顶部“余烬新闻”使用随主题变色的图标，浅色和深色背景下均可辨认。
- 插件详情会优先按脚本实际注册的扩展名定位设置；无法确认关联时可在完整设置列表中选择。
- “实时日志”页面显示核心日志快照和实时更新。暂停后恢复会重新读取当前快照。
- 管理操作记录、实时日志及详情、JS 控制台和运行时诊断在滚动区域末端预留独立间距，避免滚动条遮挡日志内容。
- “运行概览”保留核心、账号和系统摘要，不再显示核心运行日志。账号数分别为当前连接与已配置端点；运行时内存是 Go 保留的内存，不等同于进程 RSS。桌面将接口检测保留在右侧，管理操作记录独立滚动；手机在主内容中滚动查看各栏目。
- 管理接口和运行指标使用同一个 WebUI 会话。登录时可输入 UI 密码或有效会话令牌（可带 `Bearer` 前缀）；独立管理员密钥不能替代会话令牌。未登录时不请求受保护的运行指标。
- “接口连通性”检测核心服务器到 QQ 官方机器人、KOOK、Discord、Telegram、钉钉和 Slack API 的访问，不携带真实账号凭据。Telegram 直接探测 Bot API 的 `getMe`，使用固定无效占位令牌，不读取真实机器人令牌，也不跟随跨站重定向。六个平台并发检测；后端仅对未收到 HTTP 响应的平台各顺序重试一次，每次最多等待 5 秒；前端不自动重跑整组检测。收到 HTTP 响应即为可达，包括 401/403/404/405 等拒绝响应，不继续重试。可达不代表账号已授权或机器人功能正常。
- “管理操作记录”读取核心持久化的最近 20 条管理操作，跨设备共享，区分成功、已受理和失败，并完整显示 IPv4/IPv6 来源地址。来源取服务器连接的对端 IP，不信任未配置的转发头；经反向代理访问时显示代理的 IP。
- “快捷入口”支持搜索添加、移除和调整顺序；保存前可取消，设置保存在当前浏览器。手机可直接点击入口，不必展开侧栏导航。
- 运行概览的“编辑入口”与“刷新记录”使用一致的按钮尺寸和对齐边缘；手机保留 44px 的操作高度。
- 管理操作记录的标题与更新时间保持完整，桌面列表使用剩余空间独立滚动；来源 IP 的底色贴合文本，长地址在窄屏自动换行。
- “文案管理”从全局导航切换类别，在当前类别列表选择一条文案进行编辑；桌面右侧显示该文案的服务端预览、指令测试入口和可用变量，手机在编辑区下方查看这些内容。编辑说明通过弹窗打开；预览只针对已保存文案，刷新预览不会覆盖未保存草稿。
- “自定义回复”保留全局启用开关，变量与匹配帮助通过弹窗查看；未更改文件时不显示保存栏。修改后显示保存栏，成功后提示“已保存”约 3 秒再隐藏；失败或保存期间继续修改时，保留未保存状态。
- “JS 运行时”的“运行时与路由”页用卡片展示运行时状态，技术信息可展开查看，并在同页设置全局默认和扩展包路由。切换标签或刷新状态不会丢弃未保存的路由；可取消修改或保存。“上传与安装”页集中处理归档上传、进度和待重启变更；安装和卸载在 Core 下次启动时应用，不会热加载或热卸载。
- 点击“立即备份”后，范围弹窗立即关闭，页面通过 Element Plus 进度条展示提交状态、执行阶段和文件进度，并提供详细失败原因。刷新页面后恢复当前任务，提交响应中断时先确认服务器状态；任务完成后更新归档列表。手动与自动备份共享执行状态，展示模式提供独立操作反馈。
- 图片预览请求失败时，资源项显示可访问的失败提示；图片解码失败仍由图片错误占位处理。

## 部署

```bash
pnpm install
```

### 开发环境

```bash
pnpm run dev
```

### 生产环境

```bash
pnpm run build
```

### 集成测试

运行 `pnpm install`，使用 Node.js >=22.12（测试依赖全局 `WebSocket`），并确保 Chromium 可用后，在仓库根目录运行：

```bash
pnpm test
```

集成测试使用 Node.js 内置测试运行器和 Chromium DevTools Protocol，串行执行六组功能场景：备份、牌堆取消操作、新闻恢复、分页、资源预览和设置持久化。各组通过共享 harness 在 `127.0.0.1` 启动有状态 API 夹具与 Vite，使用独立缓存和 Chromium 用户目录，并在结束时释放资源。页面和组件均使用实际 Vue 实现；备份场景覆盖提交期间的弹窗关闭、进度展示及响应中断后的状态恢复。通过 `CHROMIUM_BIN` 可指定 Chromium 可执行文件路径。
